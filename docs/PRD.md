# PRD — 야자·심자 관리 시스템 (교사용 앱)

- 관련 문서: [IDEATION.md](./IDEATION.md), [ARCHITECTURE.md](./ARCHITECTURE.md)
- 대상 버전: MVP v0.1
- 상태: MVP 운영안 정리 중 (학교 확인 사항 OQ-1~OQ-8 잔여)

## 1. 제품 요약
선생님들이 작성한 Excel을 업로드하고, 담당 교사가 휴대폰에서 날짜별 야자·심자 참석 여부와 불참 사유를 기록한 뒤 결과 Excel을 다운로드하는 교사용 앱. 최종 배포 형태는 PWA 또는 Android 앱 중 아직 결정하지 않으며, MVP는 자동 알림·실시간 Excel 동기화를 포함하지 않는다.

## 2. 사용자
- **교사(Primary)**: 담당 반 야자 운영 교사 1명. 휴대폰(Chrome) 주 사용.
- **학생(Subject)**: 담당 반 20~40명. 시스템에 로그인하지 않음.

## 3. 스코프

### In-scope (MVP)
| ID | 기능 | 설명 |
|---|---|---|
| F1 | Excel 입력 | `학번, 이름, 반, 날짜, 구분` 열을 가진 Excel 업로드 |
| F2 | 슬롯 설정 | 오자/야자/심자 시간·지각 기준 편집 |
| F3 | 캘린더 예외 | 공휴일·시험기간 등록 시 Excel 대상자 생성과 출결 대상 추가 비활성 |
| F4 | 대상자 생성 | Excel의 날짜·구분별 행을 출결 대상자로 생성 |
| F5 | 출결 체크 | 참석 여부, 입실·퇴실 시각, 불참 사유 직접 기록 |
| F6 | Excel 결과 | 출결 결과를 포함한 Excel 다운로드 |
| F7 | 리포트 | 주간/월간 참석률·지각·결석 |
| F8 | 교사 인증 | 단일 패스코드 세션 |
| F9 | 운영 기록 | 업로드·출결 결과와 오류 내역 확인 |

### Out-of-scope
- 학생/보호자 화면, 자동 알림(카톡/SMS/이메일), QR 스캔, 좌석 배치, 다중 반, NEIS 연동, 건강정보·증빙자료 저장, Excel 실시간 양방향 동기화. 최종 플랫폼 결정 전의 구체적 PWA·Android 배포 작업도 제외한다.

## 4. 사용자 스토리 & 인수 조건

각 스토리는 [ARCHITECTURE.md](./ARCHITECTURE.md)의 데이터 모델·도메인 규칙을 따른다.

### US-1. 교사 로그인
> 교사로서 나는 패스코드로 로그인하여 관리 화면에 접근한다.

**Acceptance Criteria**
- AC-1.1 미인증 상태로 `/teacher/*`(로그인 페이지 제외) 접근 시 `/teacher/login`으로 리다이렉트한다.
- AC-1.2 잘못된 패스코드 입력 시 로그인 화면에 오류 메시지를 표시하고 세션 쿠키를 발급하지 않는다.
- AC-1.3 올바른 패스코드 입력 시 HTTP-only, `SameSite=Lax` 쿠키를 발급하고 `/teacher/attendance`로 이동한다.
- AC-1.4 `SESSION_HOURS`를 초과한 쿠키는 다음 요청부터 미인증으로 처리한다.
- AC-1.5 로그아웃 액션 실행 시 쿠키를 즉시 무효화한다.
- AC-1.6 서버 액션/API는 미인증 요청에 401을 반환한다.

### US-2. Excel 대상자 입력
> 교사로서 나는 선생님들이 작성한 Excel을 업로드해 날짜별 야자·심자 출결 대상자를 만든다.

**Acceptance Criteria**
- AC-2.1 Excel 필수 열은 `학번, 이름, 반, 날짜, 구분`이다.
- AC-2.2 `구분`은 `오자`, `야자`, `심자` 중 하나여야 한다.
- AC-2.3 필수 열·값이 없거나 날짜·구분이 잘못된 행은 저장하지 않고 행 번호와 오류 사유를 표시한다.
- AC-2.4 동일 학생·날짜·구분 행은 중복으로 처리하고 출결 대상은 하나만 만든다.
- AC-2.5 업로드가 끝나면 날짜별 출결 대상자 수와 오류 행 수를 보여준다.
- AC-2.6 원본 Excel 파일 자체는 서버에 장기 보관하지 않는다.
- AC-2.7 재업로드 시 기존 출결 기록은 삭제·덮어쓰기하지 않고 신규 유효 행만 반영한다.
- AC-2.8 Excel에서 빠진 기존 학생·대상자는 자동 삭제하지 않는다.

### US-3. 슬롯 시간 편집
> 교사로서 나는 학교 운영에 맞춰 슬롯 시간과 지각 기준을 편집한다.

**Acceptance Criteria**
- AC-3.1 슬롯별 시작·종료 시간을 편집·저장할 수 있다.
- AC-3.2 `lateThresholdMinutes`가 0 이상의 정수로 저장된다.
- AC-3.3 `lateThresholdMinutes` 미설정 상태에서는 지각 자동 판정을 수행하지 않고 `PRESENT`로만 기록한다.
- AC-3.4 종료 시간이 시작 시간 이후여야 한다(교차 검증).

### US-4. 캘린더 예외 관리
> 교사로서 나는 공휴일·시험기간을 등록해 Excel 대상자 생성과 출결 대상 추가를 막는다.

**Acceptance Criteria**
- AC-4.1 특정 날짜를 `HOLIDAY/EXAM/OTHER`로 등록할 수 있다.
- AC-4.2 등록된 날짜에는 Excel 대상자 생성과 출결 대상 추가 UI가 비활성화된다.
- AC-4.3 이미 대상자·출결이 존재하는 날짜를 예외로 등록하려 하면 경고를 표시한다(강제 등록은 허용하되 감사 로그에 기록).
- AC-4.4 예외일 등록 화면은 월간 달력을 바로 표시하고, 날짜를 한 번 선택해 입력할 수 있다.
- AC-4.5 대한민국 공식 공휴일·대체공휴일·선거일은 달력에 이름과 함께 표시하고 Excel 대상자 생성에서 자동 제외한다.
- AC-4.6 교사는 달력을 길게 누른 뒤 원하는 날짜까지 드래그해 연속 예외일을 한 번에 등록할 수 있다.
- AC-4.7 현재 연도는 한국 시간 기준으로 자동 전환하며, 조회한 공식 공휴일을 예외일에 자동 저장해 외부 공휴일 조회가 일시적으로 실패해도 저장본을 사용한다.

### US-5. 출결 대상자 관리
> 교사로서 나는 Excel에서 생성된 야자·심자 대상자를 확인하고 출결을 시작한다.

**Acceptance Criteria**
- AC-5.1 Excel 업로드 행마다 학생·날짜·슬롯 출결 대상과 초기 `미체크` 출결 기록을 만든다.
- AC-5.2 캘린더 예외 날짜의 행은 출결 대상으로 생성하지 않고 오류 결과에 표시한다.
- AC-5.3 동일 학생·날짜·슬롯 대상이 이미 있으면 중복 생성하지 않는다.
- AC-5.4 대상자 생성·중복 제외·예외 제외 결과를 `AuditLog`에 기록한다.
- AC-5.5 MVP에는 학생 신청, 외부 접수 승인, 신청 상세 사유 입력 UI가 없다.
- AC-5.6 교사는 출결 화면에서 필요할 때 해당 날짜의 대상자를 확인할 수 있다.

### US-6. 일일 출결 체크
> 교사로서 나는 오늘 슬롯별 학생 리스트에서 입실·퇴실·불참을 빠르게 기록한다.

**Acceptance Criteria**
- AC-6.1 기본 화면은 오늘(KST) 첫 번째 활성 슬롯을 표시하며, 슬롯 탭으로 전환 가능하다.
- AC-6.2 학생 카드에는 입실/퇴실/불참 액션이 있고, 상태는 즉시 UI에 반영된다(낙관적 업데이트).
- AC-6.3 입실 시각이 `slot.start + lateThresholdMinutes` 이후이면 `state=LATE`, 그 이전이면 `state=PRESENT`.
- AC-6.4 `lateThresholdMinutes` 미설정 시 입실은 항상 `state=PRESENT`.
- AC-6.5 퇴실 시각이 `slot.end` 이전이면 `state=LEAVE_EARLY`로 표시된다.
- AC-6.6 불참 선택 시 교사가 사유를 직접 작성할 수 있다.
- AC-6.7 불참 사유 입력 화면에는 질병명·건강정보·가정사 등 상세 개인정보를 작성하지 말라는 안내가 있다.
- AC-6.8 모든 상태 변경은 `AuditLog`에 기록된다.
- AC-6.9 과거 날짜로 이동해 상태를 수정할 수 있으며, 변경은 감사 로그에 기록된다.
- AC-6.10 출결 상태를 최종 확정하는 마감 동작을 제공하며, 마감 후 수정 이력도 남긴다.
- AC-6.11 주간 출결 화면에서 학생 이름을 누르면 교사용 상세(연락처·설문 제출/수정시간)를 조회·수정할 수 있고, 변경은 감사 로그에 값 없이 기록된다. 이 항목은 결과 Excel·CSV에 포함되지 않는다.
- AC-6.12 주간 출결 셀을 한 번 누르면 미체크·출석·지각·조퇴·결석·인정결석 중 하나를 직접 선택할 수 있다.

### US-7. 리포트
> 교사로서 나는 주간·월간 참석률과 지각·결석 현황을 확인한다.

**Acceptance Criteria**
- AC-7.1 기간 필터(주/월/사용자 지정 범위)와 슬롯 필터가 있다.
- AC-7.2 학생별 표에 대상 일수, 출석 수, 지각 수, 조퇴 수, 결석 수, 미체크 수, 참석률(%)이 표시된다.
- AC-7.3 참석률 = `(PRESENT + LATE + LEAVE_EARLY) / 처리 완료 대상 수 × 100` (처리 완료 대상 수 0이면 "-"). `EXCUSED`는 분모에서 제외하고, `미체크`는 처리 완료 대상에 포함하지 않는다.
- AC-7.4 반 전체 슬롯별 참여율 시계열 차트를 표시한다.
- AC-7.5 CSV export가 가능하며, 파일 컬럼은 화이트리스트(학번, 이름, 반, 기간 지표만)를 따르고 연락처·상세 사유는 포함하지 않는다.
- AC-7.6 Excel 결과 다운로드가 가능하며, `학번, 이름, 반, 날짜, 구분, 참석 여부, 입실 시각, 퇴실 시각, 불참 사유` 열을 포함한다.
- AC-7.7 Excel 결과 파일에는 연락처·건강정보·증빙자료가 포함되지 않는다.

### US-8. 배포 플랫폼 결정
> 운영 담당자로서 나는 PWA와 Android 앱을 비교해 최종 배포 형태를 결정한다.

**Acceptance Criteria**
- AC-8.1 PWA와 Android 앱의 사용 기기, 설치 방식, 네트워크 요구, 배포·운영 부담을 비교한 결정 기록이 문서에 있다.
- AC-8.2 최종 플랫폼이 결정되기 전에는 특정 플랫폼의 배포 작업을 MVP 완료 조건으로 간주하지 않는다.
- AC-8.3 최종 플랫폼 결정 후 해당 플랫폼의 설치·업데이트·네트워크 실패 정책을 별도 확정한다.

### US-9. 운영 기록 조회 (F9)
> 교사로서 나는 업로드 이력과 출결·설정 변경 이력을 화면에서 확인해 무엇이 언제 바뀌었는지 추적한다.

**Acceptance Criteria**
- AC-9.1 업로드 이력(`ImportBatch`)을 최신순으로 파일명·업로드 시각·행 수·오류 수·작업자와 함께 표시한다.
- AC-9.2 활동 로그(`AuditLog`)를 최신순으로 시각·작업자·액션(한글 라벨)·대상·요약과 함께 표시한다.
- AC-9.3 날짜 범위와 액션 종류로 활동 로그를 필터링할 수 있다.
- AC-9.4 활동 로그는 페이지 단위로 나누어 조회하며, 이전/다음 이동을 제공한다.
- AC-9.5 로그 요약에는 연락처·건강정보·불참 사유 원문 등 개인정보 값을 표시하지 않는다. `STUDENT_DETAIL_UPDATE`는 값 없이 변경 여부만 보여준다(P-1 준수).
- AC-9.6 이 화면은 읽기 전용이며 로그를 수정·삭제하는 기능을 제공하지 않는다.

## 5. 비기능 요구사항
- NF-1. 30명 대상 화면 렌더링 지연 500ms 이내(로컬 네트워크 기준).
- NF-2. 모든 저장은 서버 액션 또는 API 라우트에서 zod 검증 후 수행한다.
- NF-3. 모든 쓰기 요청은 인증 미들웨어 통과 필수.
- NF-4. 학생 개인정보는 브라우저 로컬 스토리지에 저장하지 않는다.
- NF-5. 접근 로그(시각·액션·actor)는 최소 필드만 남기고, 학년도 종료 + 학교 지정 보존 기간 후 파기한다.
- NF-6. KST 기준으로 날짜·슬롯 판정을 수행한다.

## 6. 데이터 보호 원칙 (개발 시 준수)
- P-1. `Attendance`/`ParticipationPlan` 스키마와 결과 Excel·CSV·감사 로그에는 연락처·건강정보를 추가하지 않는다. 학생 연락처·설문 제출/수정시간은 교사용 내부 상세 화면 전용으로 `Student`에만 저장하고 외부 내보내기·로그·외부 공유에서 제외한다. 건강정보·증빙자료·보호자 연락처는 저장하지 않는다.
- P-2. 불참 사유는 교사가 직접 작성할 수 있다. 입력 안내로 질병명·건강정보·가정사 등 상세 개인정보 작성을 금지한다.
- P-3. 외부 클라우드 배포 전환 시, 배포 문서에 학교 개인정보 담당자의 서면 승인 근거를 명시한다.
- P-4. `TEACHER_PASSCODE`, `SESSION_SECRET`은 `.env`로만 관리하며 커밋하지 않는다.

## 8. 테스트 시나리오

각 시나리오는 자동화 대상(A)과 수동/브라우저 대상(M)을 병기한다.

### T-1. 인증 (US-1)
- **T-1.1 (A)** 미인증으로 `/teacher/attendance` GET → 302, Location `/teacher/login`.
- **T-1.2 (A)** 잘못된 패스코드 → 200, 오류 메시지, `Set-Cookie` 없음.
- **T-1.3 (A)** 올바른 패스코드 → HTTP-only 쿠키 발급, `/teacher/attendance`로 리다이렉트.
- **T-1.4 (A)** 쿠키 만료 시각을 과거로 조작 후 요청 → 미인증 처리.

- **T-1.6 (M)** 로그아웃 후 뒤로 가기 → 로그인 화면 유지.

## 10. 운영 기본안과 후속 계획

### MVP 기본안
- 본 시스템은 학교 공식 출결을 대체하지 않는 야자·심자 운영 보조 도구로 운영한다.
- 교사는 학교 내부망에서 휴대폰으로 접속한다. PWA와 Android 앱 중 최종 플랫폼은 보류하며, 교외 접속은 MVP에 포함하지 않는다.
- 교사가 학생·날짜·슬롯을 직접 선택해 즉시 참여 대상으로 확정한다.
- 출결 화면에는 Excel에 등록된 학생만 표시하며, 미체크를 자동 결석으로 처리하지 않는다. 최종 플랫폼은 보류한다.
- 데이터는 학년도 단위 보관을 임시 기준으로 삼고, 학교가 정한 보유·파기 기간 확정 후 정책을 갱신한다.
- 실제 슬롯 시간과 지각·조퇴 기준은 첫 운영 전에 학교 시간표와 운영 규칙으로 설정한다.

### 후속 추가 후보
- 학교 승인 후 교외 접속, VPN 또는 승인된 외부 호스팅.
- 학생용 신청 화면과 외부 신청 채널 연동.
- 교사별 계정·역할 권한.
- Android 앱, 푸시 알림, QR 입퇴실.
- 학교 명의 카카오 알림톡 자동 발송.
- 좌석 배치, 여러 반·학년 운영, NEIS 연동.

후속 기능은 실제 MVP 사용 결과와 학교 승인 여부를 확인한 뒤 우선순위를 정한다.

## 11. 학교 확인 사항
- **OQ-1** 학교 내부망에 상시 서버를 둘 수 있는지와 서버·백업 관리 책임자.
- **OQ-2** 데이터 보유·파기 기간 및 백업 보관 기준.
- **OQ-3** 실제 반의 슬롯 시간표와 지각·조퇴 판정 기준.
- **OQ-4** 향후 학교 공식 출결 자료로 전환할 가능성과 필요한 권한·정정 절차.
- **OQ-5** PWA와 Android 앱 중 최종 배포 플랫폼.
- **OQ-6** Excel 재업로드 시 기존 기록의 추가·교체·삭제 정책.
- **OQ-7** 출결 마감 시점과 미체크 처리 기준.
- **OQ-8** 불참 사유 최대 글자 수와 결과 Excel의 보관·공유 기준.

이 항목들은 MVP 기능 방향을 다시 정하는 미결정 사항이 아니라, 실제 배포 전에 학교와 확인해야 하는 운영 조건이다.

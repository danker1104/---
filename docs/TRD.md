# TRD — 야자·심자 관리 시스템

- 관련 문서: [PRD.md](./PRD.md), [ARCHITECTURE.md](./ARCHITECTURE.md), [IDEATION.md](./IDEATION.md)
- 문서 상태: MVP 기술 요구사항 초안
- 최종 배포 플랫폼: PWA 또는 Android 앱 중 보류

## 1. 기술 목표

선생님들이 작성한 Excel을 업로드하고, 담당 교사가 휴대폰에서 날짜별 야자·심자 출결을 기록한 뒤 결과 Excel과 리포트를 확인할 수 있는 시스템을 구축한다.

기술 설계는 최종 플랫폼과 무관하게 다음 공통 흐름을 지원해야 한다.

```text
Excel 업로드
  -> 행 검증 및 오류 표시
  -> 날짜·슬롯별 ParticipationPlan 생성
  -> 교사 출결 체크
  -> Attendance 저장 및 감사 로그 기록
  -> 결과 Excel 다운로드 및 리포트 집계
```

## 2. 기술 스택

- 언어: TypeScript 5.x, strict 모드
- 런타임: Node.js 22 LTS
- 패키지 관리자: pnpm
- 애플리케이션: Next.js 15+ App Router
- UI: Tailwind CSS, shadcn/ui, lucide-react
- 폼·검증: react-hook-form, zod
- ORM: Prisma
- MVP 데이터베이스: 단일 인스턴스 SQLite
- 확장 데이터베이스: 학교 승인 후 PostgreSQL 검토
- Excel 처리: xlsx
- 날짜 처리: date-fns와 `Asia/Seoul` 기준 유틸리티
- 리포트: recharts
- 로그: pino 및 stdout
- 테스트: Vitest, React Testing Library, Playwright
- 배포 재현: Docker, Docker Compose

## 3. 시스템 구조

### 3.1 공통 구성

- 클라이언트: 교사 휴대폰 화면
- 애플리케이션 서버: 인증, Excel 처리, 출결 처리, 리포트, 결과 다운로드 제공
- 데이터베이스: 학생·대상자·출결·감사 로그 저장
- 파일 처리: 업로드 파일을 메모리 또는 임시 영역에서 처리하고 장기 보관하지 않음

### 3.2 플랫폼 정책

- PWA와 Android 앱 중 최종 플랫폼은 보류한다.
- 업무 규칙, Excel 입출력, 서버 API, 데이터 모델은 플랫폼 독립적으로 설계한다.
- PWA를 선택하면 Web App Manifest와 서비스워커를 추가한다.
- Android 앱을 선택하면 동일 서버와 데이터 규칙에 연결하는 앱 패키지 방식을 별도 결정한다.
- 최종 플랫폼 결정 전 특정 플랫폼의 배포를 MVP 완료 조건으로 삼지 않는다.
- 어느 플랫폼에서도 MVP 오프라인 출결 저장은 지원하지 않는다.

## 4. 인증과 접근 통제

- 학생 로그인과 보호자 계정은 제공하지 않는다.
- 교사 인증은 단일 패스코드 세션을 사용한다.
- 보호 대상 경로는 `/teacher/**`이며 로그인 경로는 예외로 둔다.
- 세션 쿠키는 HTTP-only, `SameSite=Lax`를 사용한다.
- 세션 기본 유효시간은 12시간이다.
- 패스코드와 세션 서명 키는 환경변수로만 관리한다.
- 모든 서버 액션과 API 쓰기 요청은 인증 가드를 거친다.
- 패스코드 실패 제한, 강제 로그아웃, 휴대폰 분실 대응은 운영 정책 확정 후 반영한다.

## 5. 데이터 기술 요구사항

### 5.1 핵심 엔터티

- `Student`: 학번, 이름, 반, 활성 상태, (교사용 내부 상세) 연락처·설문 제출/수정시간 — 결과 Excel·CSV·감사 로그·외부 공유 제외
- `ParticipationPlan`: Excel 행에서 생성된 학생·날짜·슬롯 운영 대상
- `ImportBatch`: 업로드 파일명, 업로드 시각, 행 수, 오류 수, 작업자
- `Attendance`: 대상자의 입실·퇴실·출결 상태·불참 사유
- `SlotConfig`: 슬롯 시작·종료 시각, 지각 기준, 활성 상태
- `CalendarException`: 휴일·시험일 등 운영 제외 날짜
- `AuditLog`: 작업자, 작업, 대상, 시각, 시스템 메타데이터

### 5.2 무결성

- 동일 학생·날짜·슬롯의 `ParticipationPlan`은 하나만 허용한다.
- 하나의 `ParticipationPlan`은 하나의 `Attendance`와 연결한다.
- 비활성 학생은 신규 Excel 대상자에 포함하지 않는다.
- 기존 학생의 학번·이름·반이 Excel과 다르면 자동 덮어쓰지 않고 오류 또는 검토 대상으로 처리한다.
- 명부와 출결 기록은 물리 삭제보다 비활성화·감사 로그를 우선한다.

## 6. Excel 처리 요구사항

### 6.1 입력 형식

- 기본 지원 형식: `.xlsx`
- 기본 열: `학번`, `이름`, `반`, `날짜`, `구분`
- `구분` 허용값: `오자`, `야자`, `심자` (설문 원본 제출내역/제출내역_텍스트 형식도 기준 월요일 지정 시 직접 업로드 가능)
- 학번은 문자열로 처리해 앞자리 0을 보존한다.
- 날짜는 `YYYY-MM-DD`를 표준 형식으로 사용한다.
- 첫 번째 시트를 기본 입력 시트로 사용한다.
- 빈 행은 무시한다.

### 6.2 검증 결과

- 필수 열 누락, 필수값 누락, 잘못된 날짜, 잘못된 구분을 행 단위로 검증한다.
- 잘못된 행은 저장하지 않고 행 번호와 오류 사유를 표시한다.
- 정상 행은 오류 행과 별개로 처리할 수 있다.
- 중복 행은 하나만 대상자로 만들고 중복 수를 결과에 표시한다.
- 캘린더 예외 날짜의 행은 대상자를 만들지 않고 예외 사유를 표시한다.
- 업로드 결과에는 전체 행 수, 정상 행 수, 중복 행 수, 오류 행 수, 날짜별 대상자 수를 표시한다.
- 원본 Excel 파일은 서버에 장기 보관하지 않는다.

### 6.3 재업로드

- 재업로드는 전체 교체가 아니라 유효한 신규 대상자의 추가·확인으로 처리한다.
- 이미 출결 기록이 있는 대상자는 삭제하거나 덮어쓰지 않는다.
- Excel에서 빠진 기존 학생·대상자도 자동 삭제하지 않는다.
- 동일 학생·날짜·슬롯은 기존 대상자로 판단해 중복 생성하지 않는다.
- 결과 Excel은 다운로드 시점의 현재 데이터로 새로 생성한다.

## 7. 출결 처리 요구사항

- 출결 화면에는 Excel에 등록된 대상자만 표시한다.
- 기본 조회 날짜는 KST 기준 오늘이다.
- 슬롯별 탭으로 오자·야자·심자를 전환한다.
- 상태는 `미체크`, `PRESENT`, `LATE`, `LEAVE_EARLY`, `ABSENT`, `EXCUSED`를 사용한다.
- 입실 시각과 슬롯 시작 시각을 비교해 지각 기준을 적용한다.
- 지각 기준이 설정되지 않으면 입실 상태는 `PRESENT`로 기록한다.
- 퇴실 시각이 슬롯 종료 전이면 `LEAVE_EARLY`로 표시한다.
- 불참 사유는 교사가 직접 입력할 수 있다.
- 불참 사유 입력에는 최대 글자 수 제한을 두며, 정확한 값은 학교 확인 사항으로 둔다.
- 입력 화면에 질병명·건강정보·가정사 등 민감한 내용을 작성하지 말라는 안내를 표시한다.
- 출결 수정은 허용하되 이전 값, 변경 값, 작업자, 변경 시각을 감사 로그에 기록한다.
- 슬롯 종료 후 교사가 출결 마감을 실행한다.
- 마감 후 미체크를 자동으로 결석 처리하지 않는다. 교사가 최종 상태를 직접 확정한다.

## 8. 리포트와 Excel 결과

- 기간 필터: 주간, 월간, 사용자 지정 기간
- 슬롯 필터: 전체, 오자, 야자, 심자
- 학생별 지표: 대상 일수, 출석 수, 지각 수, 조퇴 수, 결석 수, 인정 사유 수, 미체크 수
- `PRESENT`, `LATE`, `LEAVE_EARLY`는 참석으로 집계한다.
- `EXCUSED`는 참석률 분모에서 제외한다.
- `미체크`는 처리 완료 대상 수와 참석률에서 제외하고 별도로 표시한다.
- 처리 완료 대상 수가 0이면 참석률을 `-`로 표시한다.
- 결과 Excel 열: `학번`, `이름`, `반`, `날짜`, `구분`, `참석 여부`, `입실 시각`, `퇴실 시각`, `불참 사유`
- 결과 파일에는 연락처, 건강정보, 증빙자료를 포함하지 않는다.
- CSV 보조 내보내기를 제공할 경우에도 허용된 열만 출력한다.

## 9. 개인정보와 보안

- 시스템은 학교 공식 출결을 대체하지 않는 보조 도구로 운영한다.
- 학생 이름·학번·반·출결 정보만 목적에 필요한 범위에서 처리한다.
- 보호자 연락처, 이메일, 주민등록번호, 건강정보, 증빙자료는 저장하지 않는다. 학생 연락처·설문 제출/수정시간은 교사용 내부 상세 전용으로만 저장하며 내보내기·로그·외부 공유에서 제외한다.
- 브라우저 로컬 스토리지에 학생 개인정보를 저장하지 않는다.
- 외부 클라우드 사용은 학교의 개인정보·보안 승인 후에만 허용한다.
- 데이터 보유·파기 기간과 백업 보관 기간은 학교 기준을 적용한다.
- 로그에는 패스코드, 세션 값, 원본 Excel 내용 전체를 기록하지 않는다.

## 10. 성능과 신뢰성

- 20~40명 규모의 출결 화면에서 일반적인 액션은 로컬 네트워크 기준 500ms 이내에 사용자에게 반응을 표시한다.
- 저장 실패 시 낙관적 UI를 원상 복구하고 재시도 안내를 표시한다.
- 네트워크가 끊긴 상태에서는 출결 저장을 완료로 표시하지 않는다.
- SQLite 백업은 매일 1회 수행하고 최근 7일을 보관하는 방안을 기본으로 검토한다.
- 복구 테스트는 월 1회 수행하는 방안을 기본으로 검토한다.
- 데이터베이스 오류와 Excel 처리 오류는 사용자에게 이해 가능한 메시지로 표시하고 서버 로그에는 원인을 남긴다.
